#精灵-
用于解析ELF格式的可执行以及动态库文件，获取其中符号等等信息。支持静态解析以及内存中动态解析，速度快，稳定好。

# elfsym

纯 C 单文件 ELF 符号表解析器。支持**静态解析文件**与**动态解析运行中进程的内存镜像**，零依赖（不链接 `libelf`，不调用 `readelf`）。

专为 Android / Linux 逆向场景设计：一个 `.so`，静态能解出符号，动态也得能解出来。

---

## 为什么写它

安卓上抓 `libil2cpp.so` 这类库的符号时，会遇到一个常见坑：

> 同一个 so，静态解析能拿到符号，动态从内存里解析却一个都拿不到。

根本原因是 **内存里没有节表**。

- **静态** 走 `e_shoff` → `sht_SYMTAB` / `SHT_DYNSYM`
- **动态** 必须走 `PT_DYNAMIC` → `DT_SYMTAB` / `DT_STRTAB`

`e_shoff` 指向的节表区不在任何 `PT_LOAD` 段里，链接器根本不加载它。在 `/proc/pid/mem` 里那块是空洞。所以动态解析只能从程序头出发，顺着动态段找符号表。

这个工具就是把这个区别吃透之后的产物。

## 特性

| 能力 | 说明 |
|---|---|
| 双模式 | 静态（节表路径）/ 动态（段表路径），同一份代码 |
| 零依赖 | 只用 libc，自带全部 ELF 结构定义 |
| 单文件 | 一个 `.c`，`GCC` 一句编完 |
| 内存镜像重建 | 扫 `/proc/pid/maps`，按文件偏移拼回完整 so 镜像 |
| 坏页容错 | 整段 `Pread` 失败时按 4096 逐页重试，跳过不可读页 |
| DT_* 双形态解析 | 自动识别「未重定位 vaddr」与「已重定位绝对地址」两种 `DT_*` 取值 |
| 符号数推导 | 优先 `DT_HASH.nchain`，次选 `DT_GNU_HASH` 链遍历，最末兜底推算 |
| 双格式输出 | `.tsv` 九列数据版 + `.txt` 分块阅读版 |

##编译
GCC-O2-Wall-o elfsym elfsym.c
